# TurnRewind 插件实施方案（`dsh-tauri-turnrewind`）

> 状态：**已实施**（方案经确认后落地；实施结果与验证证据见文末 §11）
> 关联文档：[docs/spec/TURNREWIND.md](../spec/TURNREWIND.md)（交互稿）、[docs/AGENTS.plugins.md](../AGENTS.plugins.md)（插件规范）

## 0. 结论摘要

在 `packages/dsh-tauri-turnrewind/` 重新实现一个 turn 级工作区撤销插件，按本仓库现行「host half / client half」三层插件规范组织：

- **宿主侧**：为每个 Agent turn 在**私有 Git 快照仓**中记录 before / after 两个快照，算出逐文件 `+N -M`，写入每会话 JSON 账本；对外只暴露 2 条 HTTP 路由（summary 读、undo 写）。
- **客户端侧**：接管会话视图的 `conversation.chat.turnTail` 槽位（chain、`priority: -1`），在每一轮结束时渲染变更卡片 —— 「已编辑 N 个文件 / +x -y / 文件清单 / [撤销 ↺] / [审核]」，**撤销是真功能，其余按钮全部占位**。
- **Git 是硬前置**：会话 cwd 不在 Git worktree 内时不做快照，卡片以不可用态呈现，点「撤销」弹出 Dialog 说明原因。
- 不做：阶段一运行中实时 chip、模型提示注入、预览/审核/查看更改、redo、保留策略设置面、恢复围栏。

| # | 决策点 | 结论 |
|---|---|---|

## 2. 调研结论

### 2.1 参考项目（已克隆到 `source/`，仅参考，不拷贝代码）

| 项目 | 许可 | 取用点 |
|---|---|---|
| `source/dsh-turn-rewind`（Anionex，113★） | BSD-3 | 私有快照仓 + `refs/turnrewind/*` + 临时 index 捕获、冲突分类、工作区路径规范化 |
| `source/dsh-rewind`（Willmylife） | BSD-3 | `agent/pre-step` 屏障 + `write-tree` 快照的最小骨架 |
| `source/deepseek-harness`（官方 **0.1.5-rc.1**，sparse） | MIT | 槽位契约（`turnTail` chain 选举语义）、`ui-deliverables` 的 turn-tail 用法、agent 事件载荷、webserver 路由契约 |
| `source/dsh-auto-collapse`（a179-sanae） | MIT | **可选服务探测**写法（`ctx.inject([...], cb)` + `ctx.get`，避免一次性快照丢能力）、DOM 契约与业务分离 |
| `source/dsh-smooth-stream`（Laplace-bit） | MIT | **跨内核代模块表探测**（见 2.4 陷阱 1）、client store 自兜底、外部插件的 client bundle 纯度校验思路 |

### 2.2 已核实的平台能力

- **宿主钩子**：`agent/pre-step`（waterfall，可 await —— 天然的执行屏障）、`agent/turn-stopping`（serial）、`agent/status`、`agent/error`、`session/event`（`turn/start` / `turn/end`）。
- **客户端槽位**：`conversation.chat.turnTail` 是 **chain** 型、session 作用域，owner props 为 `{ turn: TurnLocation, seq, openFile }`，组件另获 session 标准座（`sessionId` / `useSession`）。
  - **chain 是选举制**：同一轮只渲染一个 entry（升序 `priority`，首个 `select` 非 null 者当选）。
  - 官方 `ui-deliverables` 以默认 `priority: 0` 注册该槽 → 本插件用 `priority: -1` 抢先当选即可稳定接管。
- `select` 契约要求**纯函数**（只读 owner props，禁止读外部可变状态）→ 选举决策只能基于 `owner.turn.turn`，卡片内容由组件内部按 store 状态决定。
- 仓库侧接线已就绪：`packages/dsh-tauri-bundle` 已依赖本包；`src-tauri/resources/internal-plugins.json` 已有条目（**描述文案是旧版两阶段 `/undo` 的，需同步更新**）。

### 2.3 归档版 `dsh-tauri-turnrewind-ts` 的做法与取舍

**它怎么做**：会话 cwd 必须是 Git worktree；私有快照仓 `$DSH_HOME/snapshots/<hash>.git`，通过 `objects/info/alternates` **借用源仓库对象**（附带 `rev-list --missing=print` 连通性自检与「失效即删仓重建基线」自愈）；临时 `GIT_INDEX_FILE` + `add --all` + `write-tree` + `commit-tree` + `update-ref refs/turnrewind/*`；`agent/inbox/claimed` 预留 + `agent/pre-step` await 屏障；`turn/end` 后台结算；SQLite 五表账本；恢复用逐文件 atomic bak-swap；UI 为 `/undo` 两阶段计划 + 确认。

**本方案取其骨架、弃其复杂度**：

| | 归档版 | 本方案 | 原因 |
|---|---|---|---|
| 对象存储 | alternates 借用 | 自包含 | 去掉整套自愈机制；代价是首轮把内容复制进私有仓（受源仓库 ignore 规则约束） |
| 索引 | tmpdir index，seed 源仓真实 index | 私有仓自己的 index（stat 缓存天然增量），首轮 `read-tree --empty` | 不复制用户 index，不写 tmpdir |
| 账本 | SQLite 五表 + quick_check + 备份 + 恢复围栏 | 每会话 JSON 原子写 | MVP 够用 |
| 结算 | `turn/end` 后后台 | `turn/end` 后后台 FIFO（同）+ idle 兜底 | 不阻塞 turn 边界，与参考实现一致 |
| 恢复 | 逐文件 bak-swap → rename | `git checkout <commit> -- <path>` | 由 git 负责写盘 |
| 范围 | redo / 预览 / 通知 / 恢复面板 / doctor / 保留策略 | 只做撤销 | 按需求收敛 |

### 2.4 内核版本适配（**必读**：`0.1.5-rc.1` 与 `0.1.2-rc.1`）

本插件必须同时跑在桌面端当前支持的两个内核上（本机路径）：

```text
0.1.5-rc.1  C:\Users\hairy\AppData\Roaming\io.github.hairyf.deepseek-harness-desktop\dependencies\dsh
0.1.2-rc.1  C:\Users\hairy\AppData\Roaming\io.github.hairyf.deepseek-harness-desktop\dependencies\dsh-0.1.2-rc.1-33729514615
```

上述两个安装目录**只含编译产物、不含 `.d.ts`**，因此契约核对以「官方 0.1.5-rc.1 源码（`source/deepseek-harness`，已 sparse clone）+ 两个内核的编译产物 + 前端 bundle」三方交叉验证为准。已核结论：

**A. 两内核一致、可直接依赖（无需版本分支）**

| 能力 | 0.1.2-rc.1 | 0.1.5-rc.1 | 证据 |
|---|---|---|---|
| `agent/pre-step`（waterfall，可 await） | ✅ | ✅ | agent-loop `dispatch.waterfall("agent/pre-step", …)`；载荷含 `agent`（dispatch 注入） |
| `agent/turn-stopping`（serial，turn 落定**前** await） | ✅ | ✅ | agent-loop `await this.dispatch.serial(...)` |
| `agent/status` / `agent/error` | ✅ | ✅ | dsh-agent `invariant.js` |
| `ctx.sessions`（service `"sessions"`）、`session.header.cwd` | ✅ | ✅ | dsh-session `super(ctx,"sessions")`；session types `readonly cwd?: string` |
| `session/event`（`(session, event)`，`turn/end`） | ✅ | ✅ | dsh-session emit + 官方 0.1.5 源码 |
| `ctx.webServer.register({ kind:'exact', path, handler })` | ✅ | ✅ | dsh-host-webserver `register(route)` |
| 客户端 `conversation.chat.turnTail` 为 **chain**、`select` 必填、`priority` 升序 | ✅ | ✅ | 两内核 `ui-deliverables/lib/client.js` 均以 `select` 注册该槽；前端 bundle 均含 `requires options.select` |
| 官方 `ui-deliverables` 占该槽且 **priority 默认 0** | ✅ | ✅ | 同上（0.1.2 组件名 `ProducedFiles`，0.1.5 为 `Deliverables`） |
| 客户端 locale `register(ns, locale, dict)` 与 `register(ns, { zh, en })` 两种重载 | ✅ | ✅ | 两内核 `dsh-client-locale/lib/client.js` 实现逐字一致 |
| session 槽注册的 inject 工厂首参为 `sessionId` | ✅ | ✅ | 0.1.5 `ui-slots` `InjectParams` = `[sessionId: SessionIdOf, …]` |

**B. 必须适配的差异与陷阱**

1. **模块表陷阱（最高风险，smooth-stream 的 issue #17 曾整站白屏）**
   client bundle 在 `window.__ModuleLoader__` 的 factory 里运行，`require` 只能命中**当前内核实际装载的模块表**。0.1.2 把 snapshot store 从 `dsh-client-runtime` 拆成独立的 `dsh-client-store`；0.1.5 里 `dsh-client-runtime` / `dsh-client-ui-slots` / `dsh-client-store` / `dsh-client-ui-primitives` **都已不是独立包**（并入前端静态平台模块表）。
   → **本插件 client 代码硬约束：零 `@deepseek-ai/*` 值导入**（类型导入可被擦除、无请求）。允许的 bare import 只有 `react` / `react/jsx-runtime` / `dsh-tauri/client` / `dsh-tauri-ui/client`；其余依赖由 `dsh-tauri-tsdown` 内联。
   → `dsh.client.external` **绝不能**写目标内核不存在的包名（那是硬请求）；本插件**不需要任何 external**（只用本仓库的 `dsh-tauri/client`、`dsh-tauri-ui/client` 与平台 react）。
2. **`dsh.client.inject` 只列真实存在的包名**（信息性）：`@deepseek-ai/dsh-client-ui-chat`（`turnTail` 的声明方）、`dsh-tauri`、`dsh-tauri-ui`。
3. **宿主 `inject` 只声明两内核都有的服务**：`webServer`、`sessions`、`agents`。声明星座里不存在的服务会让 fiber **永久 PENDING**（插件静默不生效）——绝不照抄旧插件的 `connection` / `workspaceRegistry` 等清单。
4. **`sessionId` 从注册 inject 工厂参数取，不依赖 `SessionStandardProps.sessionId`**：该类型合并的宿主在版本间搬过家（0.1.0 在 `dsh-client-runtime`，0.1.5 在 `ui-session`/`ui-chat`），而 inject 工厂首参在两个内核里都是框架解析好的 `sessionId`（与 `dsh-tauri-worktree` 现有写法一致）。
5. **可选服务只用 `ctx.inject([...], cb)` + `ctx.get(...)` 探测**，不用一次性 `ctx.get` 快照（auto-collapse 的教训：服务晚于插件 provide 时能力永久丢失）。
6. **槽位缺席即静默不注册**：`ctx.slots.inject(name, setup)` 会等待声明；未来内核若移除 `turnTail`，注册永不发生、不抛错、不白屏（符合本仓库「缺 renderer patch 时优雅降级」的规范）。

## 3. 架构总览

```text
用户发消息
  │
  ├─ agent/pre-step (step === 1)
  │     └─【await 屏障】before 快照（write-tree + commit-tree + update-ref）
  │        · 非 Git / 系统目录 / 超限 → 本轮标记 skipped，不阻塞 Agent
  │
  ├─ Agent 改文件（write / edit / bash / pwsh / 格式化器 / 生成脚本…全部按磁盘真实差异纳入）
  │
  └─ session/event: turn/end
        └─ 后台 FIFO（每 workspace 串行）：after 快照 → git diff --numstat → 写账本
           （agent/status → idle 兜底结算被中断的 turn）

客户端 turnTail 卡片（每一轮结束处，priority -1 接管）
  GET  /api/turnrewind/summary?sessionId=…     读本会话全部 turn 记录
  POST /api/turnrewind/undo { sessionId, turn } 冲突预检 → 还原 → 回写账本
```

## 4. 宿主侧设计

### 4.1 快照域与私有快照仓

```text
$DSH_HOME/turnrewind/
├─ workspaces/<sha256(规范化 worktree 根)[0:24]>.git/   # 每 worktree 一个私有仓
│     ├─ index                                          # 我们自己持有的索引（增量依据）
│     └─ refs/turnrewind/<sessionId>/<turn>/<before|after>
└─ sessions/<sessionId>.json                            # 账本
```

- **快照域 = Git worktree 根**：由 `git rev-parse --show-toplevel` 解析；会话 cwd 是子目录时归并到根（与归档版一致，共享同一快照域）。
- 私有仓初始化一次：`git init` + `core.worktree = <worktree 根>` + `gc.auto = 0`；此后所有 git 调用一律显式带 `--git-dir=<私有仓>`，**绝不在用户仓库里写任何对象、ref、index、stash**。
- 路径规范化：`realpathSync.native` + Windows/macOS 大小写折叠后再哈希（避免同一目录产生两个快照域）。
- **不使用 alternates**：私有仓自包含，源仓库 `git gc --prune=now` 不会破坏快照。

### 4.2 捕获（before / after 共用一条路径）

```text
git --git-dir=<D> --work-tree=<root> add -A -- .
git --git-dir=<D> --work-tree=<root> write-tree
git --git-dir=<D> --work-tree=<root> commit-tree <tree> [-p <上一次 commit>] -m "turn <n> <phase>"
git --git-dir=<D> --work-tree=<root> update-ref refs/turnrewind/<sessionId>/<turn>/<phase> <commit>
```

- ignore 语义**完全委托给源仓库**（`.gitignore` / global excludes 由 `--work-tree` 自动生效）。
- 并发：**每 workspace 一条 FIFO 队列**串行执行，避免私有仓 index 竞争；完成后清理该 turn 的 ref（账本淘汰或撤销后不再需要时）。
- 失败语义：捕获失败只 `logger.warn` 并给该 turn 记 `snapshotFailed`，**绝不打断 Agent turn**。

### 4.3 差异统计

```text
git --git-dir=<D> diff --numstat --name-status --no-renames <beforeCommit> <afterCommit>
```

- 产出 `{ path, status: 'M' | 'A' | 'D', insertions, deletions, binary }`；二进制文件 insertions/deletions 记为 `null`（UI 显示 `-/-`）。
- `--no-renames`：重命名拆成 `D` + `A`，语义简单、撤销实现无需处理 rename。

### 4.4 账本

`$DSH_HOME/turnrewind/sessions/<sessionId>.json`（原子写：`.tmp` + `rename`，复用 `dsh-tauri` 的宿主存储设施）：

```jsonc
{
  "version": 1,
  "sessionId": "…",
  "workspaceRoot": "D:\\proj",
  "workspaceHash": "…",
  "isGit": true,
  "unavailableReason": null,       // TURNREWIND_GIT_REQUIRED / TURNREWIND_UNSAFE_WORKSPACE / …
  "turns": [
    {
      "turn": 3,
      "turnStartSeq": 41,
      "beforeRef": "refs/turnrewind/…/3/before",
      "afterRef":  "refs/turnrewind/…/3/after",
      "files": [{ "path": "src/a.ts", "status": "M", "insertions": 5, "deletions": 3, "binary": false }],
      "insertions": 18,
      "deletions": 10,
      "createdAt": 1757000000000,
      "undoneAt": null,
      "unavailable": null            // 捕获失败/超限时写原因，卡片降级呈现
    }
  ]
}
```

- 保留上限：每会话 200 条 turn 记录（超出丢弃最早记录并删除其 refs）。

### 4.5 生命周期接线（`host/apply.ts`，全部经 `ctx.effect` / `ctx.on`）

| 时机 | 动作 |
|---|---|
| `agent/pre-step`（waterfall） | 仅 `step === 1`：按 turn 去重后 **await** before 快照（屏障），完成后 `next()`；本轮不可快照（非 Git / 系统目录 / 超限）时直接 `next()` 并标记 skipped |
| `session/event` → `turn/end` | 入队 after 快照 + diff + 账本写入（每 workspace FIFO，后台） |
| `agent/status` → `idle` | 兜底：结算未收到 `turn/end` 的 turn（中断/取消路径） |
| 插件卸载（`ctx.effect` disposer） | 置 disposed、释放等待中的屏障、等待在飞任务收尾 |

### 4.6 HTTP 路由（`host/routes/index.ts`）

统一用 `dsh-tauri` 的 `routeHandler` + `withConnectionAuth`（变更路由自带 loopback 限制与 JSON body 校验）。

```text
GET  /api/turnrewind/summary?sessionId=<id>
  → 200 { isGit, workspaceRoot, unavailableReason, turns: [ { turn, fileCount, insertions, deletions,
            files: [{ path, status, insertions, deletions, binary }], undoneAt, unavailable } ] }

POST /api/turnrewind/undo   { sessionId, turn }
  → 200 { ok: true, restored: [...], removed: [...] }
  → 409 { error: "conflict", conflicts: [ { path, reason } ] }
  → 400 / 403 / 404 / 500
```

校验顺序：`sessionId` 存在 → 其 cwd 解析出的 worktree 根与账本 `workspaceRoot` 一致（会话归属校验）→ turn 记录存在且未撤销 → 冲突预检。

### 4.7 撤销算法与冲突语义

```text
1. 取 before/after commit，git diff --name-status --no-renames
2. 冲突预检（改动任何文件之前）：
     · 状态 M：磁盘当前内容 hash ≠ after 中该路径的 blob hash → conflict
     · 状态 A：磁盘上该路径当前已不是 after 版本（被再改/被删） → conflict
     · 状态 D：磁盘上该路径当前存在（被重建） → conflict
   → 任一冲突：409 + 冲突清单，磁盘不变
3. 无冲突执行：
     · M / D → git --git-dir=<D> --work-tree=<root> checkout <beforeCommit> -- <path>
     · A     → 删除文件，并向上清理变空的父目录（止于 worktree 根）
4. 回写账本 undoneAt；单路径失败计入 failed 明细并如实返回（不谎报成功）
```

### 4.8 守卫、上限与失败语义

- **系统目录拒绝**：家目录本身、家目录祖先、任何盘根 → `TURNREWIND_UNSAFE_WORKSPACE`，不做快照。
- **Git 必需**：`rev-parse --show-toplevel` 失败 → `TURNREWIND_GIT_REQUIRED`，不做快照。
- **上限**：单文件 64 MB、单 turn 5000 文件、单快照 512 MB；超限 → 该 turn 记 `unavailable`，其余 turn 不受影响。
- 任何捕获/统计失败都不抛出到 Agent 链路，只落日志与账本状态。

### 4.9 Git 卫生（零污染保证，测试钉住）

私有仓之外只做**只读** `git rev-parse`。用户仓库的 `HEAD` / 分支 / index / `git status` / refs / stash **必须逐字节不变**（对应测试用例）。绝不调用 `git reset --hard` / `git checkout .` / `git clean` / `git stash`。

### 4.10 宿主目录规划

```text
src/host/
├─ apply.ts              # 钩子接线 + 路由注册
├─ constants/index.ts    # 上限、ref 前缀、错误码
```

## 5. 客户端侧设计

### 5.1 槽位接管

```ts
ctx.slots.inject('conversation.chat.turnTail', () => ctx.slots.register({
  name: 'conversation.chat.turnTail',
  select: (owner) => ({ turn: owner.turn.turn }),   // 纯函数：只读 owner props，始终当选以接管该槽
  priority: -1,                                      // 抢在官方 ui-deliverables（两内核均默认 0）之前
  locale: NS,
  inject: (sessionId) => ({ sessionId, useSummary: …, undo: … }),  // sessionId 取注册参数，不依赖 SessionStandardProps
}, TurnChangesCard as never))
```

约束（见 2.4-B）：client 代码**零 `@deepseek-ai/*` 值导入**；`select` 保持纯函数（禁止读我们的 store）；槽位若在未来内核中缺席，`slots.inject` 会一直等待而不注册 —— 不报错、不白屏。

**已知后果（需求已确认接受）**：官方 “Files changed” 行不再出现，其「点文件名在右侧栏预览」的行为随之消失。

### 5.2 卡片状态机

| 状态 | 触发条件 | 渲染 |
|---|---|---|
| `ready` | 该 turn 有记录且 `files.length > 0`、未撤销 | 完整卡片（见 5.3） |
| `undone` | 记录 `undoneAt != null` | 卡片 + 「已撤销」徽标，撤销按钮禁用 |
| `empty` | 该 turn 有记录但无文件变化 | `null`（不占位） |
| `unavailable` | `isGit === false` | 不可用态卡片 + 「撤销」按钮（点击弹 Dialog） |
| `failed` | 记录 `unavailable != null`（捕获失败/超限） | 不可用态卡片 + 原因文案 + 「撤销」禁用 |
| `pending` | 该 turn 尚无记录且会话刚结束/仍在跑 | `null` + 触发一次短暂重试（见 5.5） |

### 5.5 数据获取与重试

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **模块表陷阱**：client bundle 静态 require 了当前内核没有的 `@deepseek-ai/*` → loader 整棵树失败、界面白屏（smooth-stream 的 issue #17 实例） | client 侧零 `@deepseek-ai/*` 值导入（2.4-B1）；`dsh.client.external` 只写本仓库的 `dsh-tauri/client`、`dsh-tauri-ui/client`；CI/构建期用 dsh-tauri-tsdown 的 external 表兜底；两个内核各跑一次安装冒烟 |
| **服务声明星座不匹配** → 宿主 fiber 永久 PENDING、插件静默失效 | `inject` 只声明两内核都验证过的 `webServer`/`sessions`/`agents`；启动日志显式记录注册结果（2.4-B3） |
| 每轮一次 `git add -A` 的耗时（大仓库明显） | 私有仓 index 的 stat 缓存让后续轮次增量；ignore 交给源仓库（node_modules 天然排除）；超限直接跳过且不阻塞 turn |
| 接管 chain 槽导致官方行（含可点击文件）消失 | 需求已确认接受；后续若要保留点击，只需把文件行接到 `TurnTailOwnerProps.openFile`（一行） |
| 首轮快照把仓库内容复制进私有仓（磁盘） | 自包含是有意取舍；保留上限 + refs 随记录淘汰释放对象，必要时后续引入 alternates |
| after 快照后台结算与卡片渲染竞态 | 客户端对「新一轮无记录」做有限重试；`agent/status → idle` 兜底结算 |
| 未来内核继续漂移（槽位/事件改名） | 只依赖 2.4-A 表中逐条核实过的契约；槽位缺席时 `slots.inject` 静默不注册；`sessionId` 取注册参数而非类型合并（2.4-B4） |

**阶段一（运行中提示条）的实现取舍**

- 取数：宿主在 turn 进行期间每 1.5s 跑 `git add --all` + `git diff --numstat <beforeCommit>`，
  把读数缓存进内存（`capture.ts` 的 `entry.live`）；**先刷新私有 index 再 diff**，
  否则本轮新建的文件（还没进 index）会漏计——而「刚创建文件」正是运行中提示最需要反馈的场景。
- 接口：新增 `GET /api/turnrewind/live?sessionId=`，只读内存、不跑 git，客户端轮询频率与
  git 频率解耦；客户端 1.2s 轮询一次，`unmount` 立即停表。
- 生命周期：`beginTurn`（before 快照成功后）起表，`settleTurn` 第一件事就是停表并清读数，
  因此 turn 结束提示条必然消失（读数是过程态，不跨 turn 残留）；插件卸载时清掉所有定时器。
- 槽位：`conversation.input.dock`（list/session，0.1.2-rc.1 与 0.1.5-rc.1 均存在），
  与工作树状态条等 dock 条目并存；不依赖 `InputZone.session` 的字段形状，
  「是否在跑」由宿主回答，owner 份额里的 `running: false` 只用于提前停轮询。
